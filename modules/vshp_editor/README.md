# vshp_editor

Единая консольная программа для автоматизации работы с ERP `erp.vshp.online`:
**заливка вопросов в тесты**, **работа с библиотекой материалов** и **загрузка PDF**.
Управление — меню `questionary`, логи — консоль + `logs/vshp_editor.log`.

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/playwright install chromium

cp .env.example .env        # логин/пароль и тайминги (можно не делать — есть дефолты)
python main.py
```

## Меню

```
VSHP editor — что делаем?
» Тесты — залить вопросы в тест
» Тесты — проверить файл локально (без сети)
» Тесты — сканировать тест (только чтение)
» Библиотека — собрать ссылки на материалы без файла
» Библиотека — заменить файлы
» Библиотека — сканировать библиотеку
» Библиотека — загрузить PDF-презентации
» Показать журнал
» Показать конфигурацию
» Выход
```

**Безопасность отправки.** «Проверить файл локально» не ходит в сеть вообще.
«Сканировать» — только чтение. Сценарии, которые что-то пишут на сайт
(залить вопросы, заменить файлы, загрузить PDF), всегда показывают, что именно
уйдёт, и требуют подтверждения с `default=False`. Перед заливкой можно выбрать
«только 3 / только 1 вопрос» — пробный запуск.

## Как заливаются вопросы

Порядок одного вопроса (движки `release` и `beta`):

1. `open_create_form()` — создаются новые поля формы; пауза `VSHP_T_FORM` (1.8 с);
2. текст вопроса записывается и сверяется со страницей; пауза `VSHP_T_QUESTION` (2 с);
3. для каждого варианта:
   - создаётся поле варианта → пауза `VSHP_T_FIELD` (1.5 с);
   - записывается текст (с повторами при расхождении), ставится галочка;
   - пауза `VSHP_T_VARIANT` (1.5 с);
   - **полная проверка формы**: вопрос, все варианты по порядку, текст, пустота,
     галочки; расхождения чинятся автоматически и проверяются снова;
4. финальная сквозная проверка → `save_question()` (ждём JS-валидации, список);
5. опционально перечитывается список вопросов и подтверждается, что вопрос
   действительно на сайте;
6. прогресс пишется в `data/tests_progress.json` после каждого сохранения —
   при следующем запуске заливка продолжается с места остановки.

Разница движков: `release` ждёт инициализации CKEditor и навигации;
`beta` пишет сразу (через CKEditor, либо в textarea) и переходит по ссылкам
с `wait_until="commit"`. Тайминги и проверки у них одинаковые.

## Данные

`data/questions/*.json`:

```json
{
  "id": "test_1398",
  "url": "https://erp.vshp.online/tests/tests/1398/questions",
  "questions": [
    {
      "question": "Текст вопроса?",
      "answer": ["Верный вариант"],
      "variants": ["Неверный", "Верный вариант", "Ещё"]
    }
  ]
}
```

Файл проверяется до отправки: ≥2 варианта, верный ответ входит в варианты,
нет пустых и дублирующихся вариантов/вопросов.

## Настройка

Всё в `.env` (см. `.env.example`): сайт, логин/пароль, headless-режим,
уровень лога и тайминги `VSHP_T_*` (в миллисекундах).

## Проверка без сети

```bash
python tests/test_offline.py
```

Прогоняет логику заливки на фейковой странице: порядок действий и пауз
(форма → вопрос → пауза → поле варианта → пауза → текст → пауза → проверка),
детекция и авто-починка расхождений, отклонение некорректных данных.
Ни одного обращения к сайту.

## legacy/

Старые скрипты сохранены без изменений: `tester_main.py`, `tester_old.py`,
`Library_return.py`, `library_uploader.py`, `web_modules/`. Ими пользоваться
не нужно — их функциональность перенесена в `modules/`.
